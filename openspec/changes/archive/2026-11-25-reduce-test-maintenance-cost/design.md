## Context

动机与范围见 [proposal.md](proposal.md)。现有 `scripts/test_suite.py` 已统一普通测试、正向 race、静态检查、耗时与清理；它没有测试规模检查。两个 Git hook 除提示文字外相同，均执行分支检查和 `make verify`。CI 只在 Ubuntu 执行基础质量门；17 个 PTY 脚本尚未被 CI 自动执行，多数依赖 Go 测试二进制中的专用 helper，少数直接执行 CLI。

本轮基线是 `51c7dc3`：955 个 Go 文件中有 412 个 `_test.go`，业务/测试物理行数为 85,784/60,682；Darwin arm64 基础质量门耗时 77.132 秒，667 个普通入口、64 个关键 race 入口通过。另已运行 Task 的四个 PTY 场景和 Plan review/handoff 的双 Provider CLI 场景；这些事实不代表其余 smoke 或其他平台已验证。

## Goals / Non-Goals

**Goals:**

- 将保守测试风格和全仓至少 3:2 变成长期规则；本次交付和后续提交、CI 采用相同尺度。
- 以独立风险而非文件、功能名或测试层数决定覆盖；优先保留少量有实质断言的代表性集成和缺陷回归。
- 精简后仍能定位原生协议、持久化、安全、副作用和取消/关闭故障；将必要的真实交互验收自动化。

**Non-Goals:**

- 不修改产品能力或生产公共协议，不通过增加业务代码、压行、改文件后缀或移动测试达标。
- 不引入覆盖率门槛、逐包配额、逐 PR 增量比例、通用 mock 框架、缓存验收结果或第二套质量门。
- 不承诺保留原有穷举排列；不删除独立关键风险，仅为了行数制造未覆盖边界。

## Decisions

### 1. 全仓 3:2 长期硬校验

沿用前述审计的 Go 物理行数口径，计入空行与注释；输出额外的非空行数帮助发现格式性变化，但不引入第二套阈值。生产集合为 `cmd/`、`internal/` 中的业务 Go 源文件；测试集合包括仓库全部 `_test.go` 和专属测试支持 Go 源文件。固定 fixture、第三方/生成产物不计入业务分母，fixture 的数量和字节另列。新增加的测试专属路径必须明确分类，不能默认为业务代码。

扫描当前被验证的完整工作树：纳入受版本管理以及未忽略的新源码，忽略已删除文件；不按当前 GOOS、build tag 或本次 diff 过滤。CI 对相同文件快照必须得到相同结果。使用整数条件 `2 * P >= 3 * T`，等于阈值通过；失败输出 P、T、比例、允许的最大 T、超额行数及分包明细，不能用显示四舍五入判定通过。

新增轻量的 `make test-ratio`，由 `make verify` 在编译和测试发现前调用一次；统计和报告复用同一实现。完整质量门仍运行现有静态检查、全部普通入口和关键 race。阈值集中定义，不接受命令行或环境变量降低、告警模式、自动更新基线或包级排除。更改阈值本身必须另有明确批准的规范变更。

比例在单一策略中使用业务/测试两个正整数 3、2，比较使用整数交叉相乘，上限使用 `floor(2P/3)`；不以浮点数或四舍五入后的显示结果判定。2026-11-25 用户明确授权由旧 2:1 调整至 3:2。

选择全仓硬比值而非先前的参考值，是用户明确要求的长期约束；选择全仓而非逐包，是因为架构守卫没有对应生产包，小型资源 owner 也需要不同于值对象的测试成本。

### 2. 测试脚本一个总量预算，防止口径搬迁

Python/Shell 的测试、PTY smoke、runner、度量工具及其支持代码统一单列物理行数 S。在同一规模策略来源记录一个上限 Smax，实施验收后的实际值是首次上限；不设置语言或功能子预算。固定 fixture 只单列，不允许把可执行测试逻辑伪装成数据以排除统计。

`S > Smax` 同样使基础质量门失败。验收后的精简随变更显式下调预算；新增关键风险确需增长时，在对应 OpenSpec 中说明缺口、独立断言、净成本和实测耗时并评审调整。跨语言迁移必须同时列出原测试、替代入口与两侧净变化；仅靠预算不能机械判断语义等价，仍需风险评审。比例和预算放在单一小型策略文件中，不保存重复历史基线或每次运行自动写回。

### 3. 测试准入比比例更先决定是否值得写

新增或保留测试必须能说明它独立检出的关键业务失败、必要契约、已知缺陷、安全/持久化/并发/资源所有权故障。现有用例能够检出同一风险时扩充或复用；不按新增函数、字段或功能自动新增一套测试。满足 3:2 也不能为没有独立价值的测试提供理由。

共享机制的完整不变量在所属边界验证一次，各 Provider 和上层调用保留真实接线及其独有语义。取消与故障用确定屏障/注入，不以更多循环替代明确时序。新增 helper 必须有实际复用且净减少维护量，禁止万能 mock 和跨层测试框架。大矩阵只保留风险等价类，不把缓存模式、终端色彩、宿主、工具能力等无关维度全部相乘。

AGENTS §7 写入上述风格与硬门禁；`docs/testing.md` 保存当前统计口径、关键风险分工和简短组级删减说明。原始枚举、日志、耗时与大清单留在忽略输出目录，不形成另一套必须维护的测试台账。

### 4. 按已审计风险归属精简，不按目录整体砍掉

| 范围 | 具体收敛 | 保留的关键边界 |
|---|---|---|
| Provider checkpoint/replay | `compaction`、`task_checkpoint`、`offline_history`、`stop_hook_cache` 的共享窗口、来源及生命周期统一验证 | 两家固定 current bytes、decoder 接线、连续 checkpoint、uninterrupted/restored canonical bytes、原生顺序与 fingerprint |
| Provider input/output | `file_input`、`steering`、`stop_projection`、`session_start` 及 Hook/Task 工具输出按共享机制与原生适配拆分 | 各家真实角色/形状、opaque fidelity、冻结证据、严格 Tool 参数及拒绝伪造 native |
| Provider stream | cache × trigger × failure、capability × chunk × terminal 收敛为风险代表 | 真正不同的 wire 终态解释、UTF-8/分包、真实 HTTP 取消、唯一终态及失败不提交 |
| app 成功链路 | 共享 resume/headless 三轮恢复装配；删除重复 Read-only 成功 E2E；收缩 skill/plugin 来源 × 宿主成功组合 | 各 Provider pairing、参数接线、取消、崩溃、冻结恢复、权限与 sandbox |
| TUI | 普通展示、滚动及编辑成功路径由必要固定快照和自动化 PTY 承接 | hydration、过期回复、跨会话状态、审批焦点、取消与关闭 |
| Session/runtime | 统一固定坏前缀拒绝修复、artifact Sync 授权装配和语义相同的 journal fake | 实际提交点、失败 bytes 不变、lease、poisoned、进程所有权与 TOCTOU |

具体纠错先于依赖相关断言删减：

- `session/task_progress_test.go` 删除只验证测试自写 `taskProgressBefore` 的矩阵，改用真实 record prefix 经过生产 replay 检查；保留 runtime 的 `completed -> pending -> clear` 实时序列，app 目前不能替代这一覆盖。
- 两家的 `post_output_test.go` 为伪造 native 检查提供有效 ThreadID，先证明原始 records 成功，再只破坏 output 验证拒绝，避免无关来源校验提前报错制造假通过。
- `app/resume_e2e_test.go` 的 identity answer/nil browse 死参数与不可达 Markdown helper 删除；completion 的单值参数维度收掉。

公共 Provider 测试优先使用 external `provider_test` 和既有公共入口，避免根包导入子适配器造成循环。必须保留私有构造的场景使用窄 typed adapter；跨包共享普通 `.go` 支持文件统一归入测试，正式 CLI 依赖图不能包含它们。不得导出 native history 或请求编译方法供测试调用。

### 5. 原生 PTY 纳入本地 pre-commit

保留 `make verify` 作为本地 pre-commit 和 CI 的基础质量门。按用户 2026-11-25 的最新授权，pre-commit 在 verify 成功后执行同一 `make smoke`，远端移除 smoke job。该计划覆盖实际 CLI/PTY 输入、审批、任务/会话展示、恢复、取消和终端还原；每次提交都须取得实际完成结果，不使用成功缓存、条件跳过或仅告警。现有 ACK helper 是执行基础，不能因文件带 `_test.go` 而删掉；普通 Go 测试中的 helper return 不算 PTY 完成。

按既有 scripts 的实际承接选取场景，重点包括 tasks、completion、session-picker/titles、plugins、user-question、file-mentions/effort、reasoning/markdown、Hook/compaction、plan-mode 与 session-start；保留每项独立风险，消除重复色彩/Provider/配置的笛卡尔积。共享编译一次 app.test、tui.test、CLI 后复用，不要求迁移不受本轮影响的脚本接口。必须记录实际场景完成、断言、退出和 cleanup；不支持的平台明确拒绝执行，不能以跳过计为通过。

本地开发先完成自动化入口并实际运行通过，才迁移由它承接的重复交互断言。pre-commit 依次运行分支检查、verify 和 smoke；前一步失败立即退出，smoke 的失败或不支持平台同样阻止提交。更新 PR 模板，要求本地 hook 通过，并仅将 branch-governance 与 verify 列为远端检查；GitHub ruleset 的启用单独核实，尚未启用的远端强制保护明确列为未完成保障，不声明仓库 YAML 已自动修改远端设置。smoke 不代表全部 Darwin Go 测试，更不能替代 Sync、lease 或原生 wire 故障回归。

### 6. 删除 pre-push，保留单一本地完整验证

删除 `.githooks/pre-push`，保留 `.githooks/pre-commit` 的分支检查，随后执行 `make verify` 与 `exec make smoke`，用既有 `set -eu` 保证失败即停止。`make install-hooks` 继续设置 `core.hooksPath=.githooks`，只为现存 hook 和分支脚本设置权限；不清理用户 `.git/hooks`，不添加迁移脚本、软链接、共用 wrapper 或第二个调用入口。

同一提交之后的 push 不再本地重复验证；CI 仍独立验证实际提交。提交后再改成非法分支名，不再由本地 push 拦截，而由 PR branch-governance 检查处理。同步 `engineering/branch-governance` 和 `engineering/test-execution`，历史验收记载保留当时事实并追加当前策略说明。

## Risks / Trade-offs

- [第二轮净减尚待实际验证] → 当前 T=60,938、P=88,048，3:2 的上限为 58,698，需净减 2,240。先审 app Hook/PTY 装配、Provider 镜像和核心重复成功验证，再按包括 helper 的净值收口；目标未达时仍不得删独立关键风险或自动改阈值。
- [代表性覆盖会放弃排列组合] → 在组级说明保留的不变量与删除维度；不声称与旧集合等覆盖，持续保留已知缺陷最小回归。
- [严格比例也会被删除业务代码影响] → 规则仍按最终全仓快照执行；不能靠保留 dead code、增加包装或改分类维持分母。遇到实际冲突按规范变更处理，不能自动豁免。
- [共享测试过度抽象] → 保留协议专属 fixture/decoder；仅提取明确共享生命周期，计算 adapter 后净收益，不建立测试框架。
- [脚本预算使必要新增交互受限] → 对应功能的 OpenSpec 同时说明必要成本和预算调整，不增加独立审批系统；3:2 主阈值保持不变。
- [每次本地提交增加原生交互耗时] → 按用户要求强制执行既有 61 场景，复用三个构建产物，不增加矩阵；记录完整 hook 耗时。smoke 当前仅支持原生 macOS，其他平台明确失败，不自动跳过。取消远端 smoke 后不再依赖托管 macOS 资源排队。

## Migration Plan

先实现度量报告和最小计数器回归，按上述组完成精简、纠正无效断言、接入承接的 PTY；在最终满足 `2P >= 3T` 后启用硬门禁并锁定脚本预算。未满足门槛的中间工作不作为完成交付，不留下长期 warning-only 模式。

完成单 hook 切换、文档与两份规范同步，执行最终完整质量门和对应原生 smoke、静态/平台编译检查。若迁移造成回归，恢复该组最小有效测试并重算；不通过跳过测试、调低比例或自动涨预算回滚质量保障。原始证据保存在忽略目录，归档只保留简短结论。

## 历史实施复核（2026-11-24，目标未完成）

实际计入新增普通 Go 测试支持与 adapter 后，P 保持 85,784，T 从 60,682 降为 58,482，净减 2,200；比例为 1.4668:1，达到 2:1 仍需净减 15,590 行。脚本从 4,572 增为 4,892，新增成本来自统一 smoke 执行/回执/清理及度量自检；未将 Go 断言搬到脚本中规避主比例。脚本最终验收预算尚未锁定。

Provider 净减 1,119，app 净减 622，TUI 净减 157，核心与 headless 净减 305，架构依赖守卫净增 3。原候选估算显著高估了可净删的文本：成对文件的协议差异和窄 adapter 要保留；场景本来采用循环，减少矩阵主要减少执行次数。Provider 新 testsupport 的 1,634 行已计入 T，不产生业务分母。

第二轮检查没有证实可继续净减约 1.56 万行的等价重复：app Task/Plan 的 2,069 行包含真实 CLI、冻结恢复与审批；app session 与 Session 持久化约 3,783 行包含不同 native、Sync、lease、TOCTOU 边界；runtime 主要七文件 3,338 行覆盖不同提交点和取消/关闭时序；Tool/extension/context 约 3,540 行有独立副作用、owner 与缓存身份；headless 约 1,254 行覆盖不同 I/O 阻塞和退出边界。这些是审计时组体量，不是可删除预算。尚存小型查询/循环装配已继续合并；Hook 宿主装配约 1,087 行可再审，但不能视为整组可删，更不足以证明达标。

因此停在 task 7.1 的设计取舍点：保留 2:1，不启用虚假的通过状态，不把本 change 标为完成，也不把独立风险测试整体删除。后续若继续达标，需要重新评审测试分层与更大范围共享装配的具体方案，列出可兑现净成本及关键风险承接；本次证据不能证明 2:1 理论不可达，也不能承诺再一次模板合并就可达。

## 2026-11-25 主线整合与新增测试策略

main 从 51c7dc3 快进至 5b283ea，包含 8288d3c 与 67e47c4 的新行为。既有未提交改动先存入命名 stash，再在快进后恢复；无文本冲突仍须做语义核对。SSE 保留 gzip 首帧、空闲取消、decoder 失败关闭与已有 UTF-8 边界；历史回合保留切点、许可、原始 prefix 与独立恢复；提示钩子保留无副作用拒绝、输入归属、冻结证据和取消/关闭。重复记录器、cache 查询与纯成功排列复用，原有关键 race 名称保持可审计。

实际远端验证使用现有 DeepSeek 的 Responses 与 Messages 配置及相应授权凭据，构建正式 CLI，使用合成短文本和隔离 HOME/工作区，检查同会话与 --resume 的上下文和持久化终态。原生 PTY 交互继续核对拒绝取回/编辑与终端恢复；历史分支以原始 journal 切点与 source bytes 验证。网络配置仅作用于验收进程，不修改用户全局配置。

## 2026-11-25 用户确认的 3:2 后续实施

用户选择继续保留 change，并明确允许 3:2；历史段落中的 2:1 和差额仅记录当时验收，不再作为当前门槛。当前业务代码不变时，T 须从 60,938 降至最多 58,698。继续原有的风险归属与共享装配方案，禁止通过压行、搬迁统计、增加生产代码或删除独立安全/持久化/并发边界达标。

先统一 proposal/specs/tasks 的整数 3:2 契约，再实施第二轮 app、Provider 与核心装配精简。每组落地后重算净成本；实际满足比例后把同一只读检查前置接入 verify，按最终脚本实际总量锁定首次预算，更新 AGENTS、主规格与维护文档。推演须包括刚好 3:2、少一行业务或多一行测试、生产代码缩减、脚本超额和测试支持移动，证明失败不会进入编译/测试，也不会回写预算。沿用已有计数器自检，避免再建矩阵或框架。

代码稳定后重新执行完整 verify 和受迁移影响的原生 smoke/平台检查；生产代码和实际 CLI 未改时复用刚完成的真实八轮会话证据，不无依据重复外网请求。未提交快照没有实际 CI 记录时保留该项未完成；用户最终明确授权带该未完成项归档，保留 CI 待办与实际验收边界。

## 3:2 实施收敛

第二轮实际净减 2,453 行后，P=88,048、T=58,485，已满足 3:2；全部测试辅助计入 T。除领域装配外，runtime/session 将 364 处完全相同的错误检查复用为各包一个 `testing.TB`/error 小函数，保持原 err 作用域、FailNow 和调用栈归属，不建立断言框架。TUI 代表性承接明确缩小普通布局排列，关键固定字节、owner/Sync/lease/取消仍在。脚本预算锁定实际 4,930，后续运行只读；历史验收及原 CI 待办的后续调整见 verification。

提交阶段发现临时 Git 自检必须隔离 hook 的 GIT_* 定位环境，否则会修改真实仓库配置；在原用例中净增 3 行完成隔离，脚本预算据此显式修订为 4,933。带 hook 环境的最小回归同时验证真实 config 字节不变，不增加测试矩阵。
