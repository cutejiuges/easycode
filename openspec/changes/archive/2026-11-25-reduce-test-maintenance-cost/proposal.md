## Why

测试维护风格缺少可执行约束：在 `51c7dc3` 基线上，全仓业务 Go 为 85,784 行、测试 Go 为 60,682 行，业务与测试约 1.41:1，AGENTS 中的 4:1 参考值未进入质量门。用户已确定改为长期克制的风险导向测试、至少 3:2 的持续硬校验（2026-11-25 用户明确修订），并移除 pre-commit 与 pre-push 的重复完整验证。

## What Changes

- 将新增测试限定为关键业务链路、必要契约节点、已知缺陷及高风险并发、持久化、安全和资源所有权场景；同一机制在所属边界集中验证，上层只保留必要接线和真实 I/O。
- 精简 Provider 镜像、跨层重复成功链路、实现镜像、无效断言及过度组合；保留双 Provider 原生协议、恢复、缓存和副作用故障边界，明确接受重复排列覆盖集合缩小。
- 新增单一测试规模度量入口并接入 `make verify`：全平台业务 Go 行数 `2 × P >= 3 × T`，其中测试专属支持代码也计入 `T`；测试脚本另设一个总量预算，防止跨语言搬迁规避。
- **BREAKING**：3:2 是本次完成条件及后续默认硬门禁，不再是告警或一次性目标。现有基线尚不满足，必须完成精简后才能交付；不提供自动放宽、按包豁免或自动更新预算。
- 为关键真实交互建立本地 `make smoke` 代表性场景入口，pre-commit 在 `make verify` 成功后强制执行；取消远端 smoke，任一阶段失败均阻止提交。由冒烟承接的交互断言必须在自动化生效后才删除。
- 删除 `.githooks/pre-push`，保留 pre-commit 的分支检查、完整 `make verify` 与 `make smoke`；同步安装入口、规范、AGENTS、测试维护说明、Roadmap 和 CI 检查说明。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `engineering/test-execution`：长期风险导向测试、全仓 3:2 硬校验、测试支持与脚本统计、防规避、原生交互验收，以及单一本地 Git hook。
- `engineering/branch-governance`：本地分支检查由 pre-commit 执行，移除 pre-push 的重复要求，保留 CI 独立检查。

## Impact

- 涉及 `internal/**/*_test.go`、`cmd/**/*_test.go`、必要的测试专属支持、`scripts/`、Makefile、`.githooks/`、`.github/` 与工程规范；不变更产品行为、生产公共 API、Provider wire 或 Session 格式。
- 以第二轮开始时 P=88,048、T=60,938 推演，3:2 要求 T 最多 58,698 行，仍需净减 2,240 行。第二轮在既有风险分层内收敛 app、Provider 与核心的重复装配和低价值成功排列；按含 helper 的实际净值核对，不把估计当作已达标。
- 实施须逐组记录保留风险与删除依据。若剩余缺口只能通过移除独立关键风险保障弥补，暂停并提交具体取舍更新，不能悄悄降阈值或声称完成。
- 不新增第三方依赖，不为测试共享导出生产内部接口，不设置逐包或逐 PR 的增量比值。托管平台 required checks 的实际启用需单独核实，仓库文件更新不代表 ruleset 已生效。
