## 2. 模式控制与操作生命周期

- [x] 2.1 在交互 ChatSession 的附件准备和交接接缝接纳模式控制，AgentLoop 只在真实空闲时确认。用确定性门闩验证准备中、起始/收口、排队、压缩与交接拒绝及先后顺序。
- [x] 2.2 沿用命令相关身份、近期去重及关闭路径。验证接纳前调用方取消或宿主关闭不变更模式，接纳后迟到取消返回实际状态，有界账本内的重复命令被拒绝，错误或流关闭后入口占用释放。
- [x] 2.3 由 owner 独立设置模式与 effort，在接纳新操作时共同捕获。验证两种设置顺序、Plan 中变更与重置 `/effort`、活动时变更只影响后续操作，且同轮追加、工具、压缩及 Stop 续轮保持已捕获策略。退出操作本身零新输入、原生记录或 Provider 请求。

## 3. Provider 请求、估算和恢复等价

- [x] 3.1 用同一固定规划指令编译实际普通请求和上下文 identity。验证 `provider_profile` 只估算一次实际指令、`tool_catalog` 来源覆盖七项实际定义、`/context` 空闲时反映生效模式、默认模式维持原 fingerprint。
- [x] 3.2 接入 Anthropic `system` 和 OpenAI `instructions`，共享当前普通编译接缝并保留原生调用、结果及 opaque 推理顺序。以两家请求 golden 验证 Plan 与默认正文、Anthropic TTL 编译副本及 OpenAI HTTP/WS 属性。
- [x] 3.3 复用请求证据和缓存失效规则。在同一可续写 WebSocket 测试实际采样的模式变化触发 `request_properties_changed`，同模式增量仍发送 Plan 指令，未采样往返保持既有资格。验证 `/cache` 只推进成功普通基线，变化首来源与目录指纹各自正确，失败或摘要沿既有独立收据及重置语义。
- [x] 3.4 将摘要 wire 与普通 Plan 候选窗口分开传递。验证手动和自动摘要既有禁用工具、独立预算和只读 Hook 信任，之后普通回合仍使用 Plan 指令和目录，checkpoint 不带模式标记。
